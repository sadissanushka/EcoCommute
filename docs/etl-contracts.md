Module 5 acts as the central analytical aggregator for the Corporate Employee Shuttle & Commute Platform. It consumes operational data generated by Modules 1, 2, 3, and 4, transforms it through scheduled idempotent ETL jobs, and loads it into the `analytics` PostgreSQL schema.

## 2. Source Table Contracts

### 2.1 Module 1: Routing Engine & Matches
- **Source Tables/Views:** `core.trips`, `core.trip_participants`, `matches`
- **Key Columns:**
  - `trip_id` (`BIGINT`, PK)
  - `kind` (`TEXT`: `'carpool'` | `'shuttle'`)
  - `driver_user_id` (`BIGINT`)
  - `started_at` (`TIMESTAMPTZ`, UTC)
  - `ended_at` (`TIMESTAMPTZ`, UTC)
  - `distance_km` (`FLOAT`)
- **SLA & Sync Frequency:** Hourly incremental pull via `started_at >= watermark`.

### 2.2 Module 2: Fleet & Booking Service
- **Source Tables/Views:** `booking.bookings`, `booking.shuttle_schedules`
- **Key Columns:**
  - `booking_id` (`BIGINT`, PK)
  - `trip_id` (`BIGINT`, FK)
  - `user_id` (`BIGINT`, FK)
  - `company_id` (`BIGINT`, FK)
  - `seat_number` (`INT`)
  - `status` (`TEXT`: `'confirmed'` | `'boarded'` | `'completed'` | `'cancelled'`)
- **SLA & Sync Frequency:** Hourly batch pull; updates seat utilization metrics.

### 2.3 Module 3: Wallet & Carbon Accounting
- **Source Tables/Views:** `wallet.ledger_entries`, `carbon.trip_emissions`
- **Key Columns:**
  - `trip_id` (`BIGINT`)
  - `co2_kg` (`REAL`): Direct trip carbon emissions
  - `co2_avoided_kg` (`REAL`): Baseline solo emissions minus shared emissions
  - `fuel_reimbursed_minor` (`BIGINT`): Total reimbursement paid to driver in minor units (LKR cents)
- **SLA & Sync Frequency:** Near-real-time or hourly.

### 2.4 Module 4: Real-time Tracking & Safety Layer
- **Source Tables/Views:** `safety.incident_logs`, `safety.anomalies`
- **Key Columns:**
  - `incident_id` (`BIGINT`, PK)
  - `trip_id` (`BIGINT`)
  - `company_id` (`BIGINT`)
  - `anomaly_type` (`TEXT`: `'route_deviation'` | `'prolonged_stall'` | `'sos_trigger'`)
  - `resolved_at` (`TIMESTAMPTZ`, UTC)
- **SLA & Sync Frequency:** Hourly aggregation (counts only; personal identity scrubbed).

## 3. Data Transformation & Load Protocol

### 3.1 Watermark & Idempotency Rules
1. Every ETL run tracks its position in `analytics.etl_watermarks(source, last_loaded_at)`.
2. All loads use `INSERT ... ON CONFLICT (trip_id) DO UPDATE SET ...` to guarantee exact idempotency.
3. If an ETL job is interrupted and retried, zero duplicate fact rows are created.
4. Following fact table updates, materialized views are refreshed via:
   ```sql
   REFRESH MATERIALIZED VIEW CONCURRENTLY analytics.mv_trips_by_department_day;
   REFRESH MATERIALIZED VIEW CONCURRENTLY analytics.mv_occupancy_by_route_day;
   REFRESH MATERIALIZED VIEW CONCURRENTLY analytics.mv_fuel_reimbursed_month;
   REFRESH MATERIALIZED VIEW CONCURRENTLY analytics.mv_co2_by_company_month;
   REFRESH MATERIALIZED VIEW CONCURRENTLY analytics.mv_zone_flow_hour;
   ```

### 3.2 Time-Zone Boundary Standardization
All raw database timestamps are stored in strict UTC (`TIMESTAMPTZ`). For reporting and day-grouping, the ETL standardizes to Sri Lanka Standard Time (`Asia/Colombo`, UTC+05:30) using:
```sql
(started_at AT TIME ZONE 'Asia/Colombo')::DATE AS day
```

## 4. Privacy & Access Control Guarantees

| Principal | Access Level | Data Granularity | Privacy Mechanism |
|---|---|---|---|
| **Company Admin** | Scoped to own `company_id` only | Department, route, and daily aggregate facts | Multi-tenant row filter derived strictly from JWT `companyId` |
| **Government Policymaker** | Multi-company urban flow view | City zone grid (1 km / 4 km), hour buckets | **$\epsilon$-Differential Privacy** (Laplace noise) + **$k$-Anonymity** ($k \ge 5$) suppression |
| **Public / Unauthorized** | No access | None | Authentication required (`401 Unauthorized`) |
